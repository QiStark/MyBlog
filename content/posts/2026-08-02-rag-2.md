## 1. 语义向量检索算法

### KNN

**KNN（K 近邻算法）**：查询与 Prompt 向量最近的 K 个文档，但是计算量随着文档数量线性增加——比如 10 亿文档就要计算 10 亿次，搜索慢。因此就有了 ANN 算法的出现。

![KNN 计算量示意](/images/rag2-knn.png)

### ANN

**ANN（近似最近邻算法）**：trade-off 是牺牲一定的准确性，换取速度的提升，具体算法名称为 **Navigable Small World**。

**算法逻辑**：文档看作节点，计算节点之间的距离，距离近的文档生成边，从而生成邻近图。通过邻近图，可以通过边从一个文档跳到其最近的邻居来遍历网络。

**具体过程**：

- S1、在邻近图中随机选取节点作为候选节点，找到候选节点的邻居节点；
- S2、计算邻居节点与查询向量的距离，距离最近的作为新的候选节点；
- S3、重复 S2，直到没有邻居比当前候选者更接近，返回候选向量。

![ANN 遍历示意](/images/rag2-ann-nsw.png)

### HNSW

Navigable Small World 的升级版：**Hierarchical Navigable Small World (HNSW)**，字面理解就是引入了分层结构。

**核心思想**：利用多层稀疏图实现"先粗定位，再精搜索"。类比：飞机飞到城市（最高层）→ 开车到街区（中间层）→ 步行找到具体门牌（底层）。

![HNSW 分层结构](/images/rag2-hnsw.png)

明显减少计算量，**在构建网络的时候计算量很大，但是可以提前构建好**。

![HNSW 构建成本](/images/rag2-hnsw-build.png)

## 2. 文档分块

**为什么要分块？**

用所有文档编码，信息被平均了，导致搜索相关性差。

**分块大小设置？**

- **太大**：面临与不分块一样的困境，不能捕捉文档的细节。
- **太小**：丢失上下文信息。

**分块方法**

### 固定 size 分块

为了保留上下文关系，**分块之间会有重叠部分**。

![固定分块与重叠](/images/rag2-chunk-fixed.png)

### 递归字符文本分割

根据特定字符分块（比如换行符），保留了文档结构。

![递归字符分割](/images/rag2-chunk-recursive.png)

### 语义分块

Semantic Chunking（语义分块）的流程如下：首先按句子依次遍历整个文档，将当前文本块（Chunk）与下一句分别编码为向量表示，并计算两者之间的余弦距离（Cosine Distance）；若距离低于预设阈值，说明语义相近，则将该句加入当前文本块；若距离超过阈值，则认为语义发生明显变化，结束当前文本块并创建新的文本块。从而使每个 Chunk 内部保持较高的语义一致性，而不同 Chunk 之间具有明显的语义边界。

![语义分块](/images/rag2-chunk-semantic.png)

### LLM 分块

比如让大模型按照语义分块。

### 上下文感知分块

首先进行 LLM 分块，并要求在分块中添加摘要信息（阐明在整个文档中的上下文）。

**分块策略**：

- 应根据性能需求与实现成本进行权衡：固定长度和递归分块适合作为默认方案；
- 语义分块和 LLM 分块效果更好但实现更复杂；
- 上下文感知分块能够进一步提升效果，是一种值得优先尝试的优化方向。

## 3. 查询解析

### 查询重写

用户的 prompt 质量太差（比如啰嗦、描述不专业），因此重写 prompt。

![查询重写](/images/rag2-query-rewrite.png)

### 命名实体识别

通过识别问题中的**人物、地点、组织、日期等关键实体**，过滤实体，减少搜索范围。工具：GLiNER2。

![命名实体识别](/images/rag2-ner.png)

### 假设文档嵌入（HyDE）

让 LLM 生成答案，然后用答案检索文档。

![HyDE](/images/rag2-hyde.png)

### ColBERT

![ColBERT](/images/rag2-colbert.png)

计算示意图：在文档中找到与 Prompt 中 token 相关分的最大值。

![ColBERT MaxSim 计算](/images/rag2-colbert-maxsim.png)

| 方法          | Query 表示              | Document 表示           | 交互方式                                                    | 速度     | 精度     |
| ------------- | ----------------------- | ----------------------- | ----------------------------------------------------------- | -------- | -------- |
| Bi-Encoder    | 1 个向量                | 1 个向量                | 向量余弦相似度                                              | ⭐⭐⭐⭐⭐ | ⭐⭐⭐     |
| **ColBERT**   | **每个 Token 一个向量** | **每个 Token 一个向量** | **每个 Query Token 找最相似的 Document Token（MaxSim）**    | ⭐⭐⭐⭐    | ⭐⭐⭐⭐☆   |
| Cross-Encoder | 不单独编码              | 不单独编码              | Query 和 Document 一起输入 Transformer，全程 Attention 交互 | ⭐        | ⭐⭐⭐⭐⭐   |

## 5. 重排名

提高检索质量，针对单个文档进行，计算量大，因此不用于海选。

![重排名](/images/rag2-rerank.png)

**方法**：

- **交叉编码**：计算上下文相关性
- **LLM 打分**：微调后的 LLM，直接输出评分
